01Genting Casino UK

TIBCO to Azure Migration

Genting was paying heavily to keep TIBCO BusinessWorks and EMS licensed, so we moved the estate onto Azure. Every existing workflow had to behave identically after the move — same file movement, same transformations, same failure behaviour. I mapped each TIBCO capability to its Azure equivalent rather than redesigning: SFTP stayed SFTP, database connections stayed direct, EMS queues became Service Bus, and event triggers moved to Event Grid.

Most of the payloads were XML. I worked through the existing XSD schemas and XSLT transforms, reused them where they still held up, and wrote new XSLTs where the logic had to change. JSON flows were rebuilt the same way.

02Sephora US

SFTP Estate Migration with Parallel Cutover

Sephora was decommissioning SFTP servers that a large part of their integration estate depended on. Instead of a hard switch, I built a parallel branch into each affected workflow — every payload still went to the legacy endpoint and was routed to the replacement at the same time, so both ran side by side until the old servers could be retired without risk of dropped files.

Work came in through Jira. For each ticket I traced the existing workflow, grouped it into a container keyed on its source and destination pair so related interfaces sat together, and built to the client's established Logic Apps naming standard. Concurrency limits handled latency-sensitive routes; stateful workflows where a run needed tracking, stateless where it didn't. Java proxies kept third-party vendor traffic off publicly exposed endpoints, and XSLT and JSON schema transforms shaped each payload into the format its receiving system expected.

03Nestlé US

SharePoint to Synapse Data Pipeline

Nestlé's source files arrived in SharePoint. A Logic App collects them and lands them in Blob Storage, where ADF Data Flows do the shaping — joins, deduplication, column renaming and cleanup — before the curated result loads into Synapse.

Once a load completes, a second Logic App is invoked with the run details and publishes a sample file back into SharePoint, so the business can see what actually landed without opening a query tool. I also ran the ongoing support and enhancements: new files and sources wired in as they appeared, and business requests turned into pipeline changes that had to produce numbers the stakeholders would trust.

04P&G · 3 regions

ETL & Lakehouse Platform for P&G

Batch ingestion and transformation pipelines in ADF and Databricks, with parameterised SQL Server procedures doing the heavy set-based work. Orchestration replaced the recurring manual steps and cut hands-on intervention by half across the Mumbai, Hyderabad and Singapore teams.

Curated data landed in Delta Lake layers on ADLS Gen2, structured Bronze through Gold — ACID transactions and schema handling done properly, so downstream teams stopped reading half-written tables, with Unity Catalog handling governance.

0540GB · 14,000 files

Delta Table Performance Rescue

Months of hourly merges had left a Synapse Delta table with 14,000 Parquet files across 40GB, most of them under 2MB. Spark spent close to a minute planning before it read a single row. Fixed with OPTIMIZE, Z-ORDER, a corrected partitioning strategy and VACUUM.
